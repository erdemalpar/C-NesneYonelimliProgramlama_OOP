// 1. Temel Yapı Taşları
public interface IVarlik { void Tanimla(); }
public abstract class Hayvan : IVarlik {
private int _enerji; // Field (Veri)
public string Isim { get; set; } // Property (Özellik)
public static int Sayisi = 0; // Static (Sınıfa Ait)
public Hayvan(string isim) { // Constructor (Yapıcı)
this.Isim = isim;
}
}
// 2. Dört Ana Prensip
public sealed class Aslan : Hayvan { // Kalıtım & Sealed
public Aslan(string ad) : base(ad) { // base Keyword
Hayvan.Sayisi++;
}
public override void SesCikar() { // Polimorfizm - Override
Console.WriteLine("Kükredi!");
}
~Aslan() { Hayvan.Sayisi--; } // Destructor (Yıkıcı)
}

01. TEMEL YAPI TAŞLARI

Sınıf (Class) vs Nesne (Object) Sınıf mimarın çizdiği projedir, Nesne ise o projeden inşa edilen GERÇEK binadır. Proje bellekte yer tutmaz, bina tutar.
Alanlar (Fields) vs Özellikler (Props) Alan verinin ham halidir (private). Özellik (Property) ise veriye get/set kontrolleri eklenmiş "akıllı" halidir.

02. DÖRT ANA PRENSİP

Kapsülleme (Encapsulation)

Nesnenin iç işleyişini ve verilerini dış dünyadan gizlemek, onlara sadece BELİRLİ YÖNTEMLERLE (get/set) erişilmesini sağlamaktır.

Polimorfizm (Çok Biçimlilik)

Bir nesnenin farklı durumlarda farklı davranışlar sergileyebilmesidir.

Overloading Parametre çeşitliliği.
Overriding Atadan gelen davranışı ezme.

03. DERİNLEMESİNE SOLID MİMARİSİ

S Single Responsibility (Tek Sorumluluk)

Mantık: Bir sınıfın değişmek için sadece tek bir nedeni olmalıdır.
Uygulama: Projemizde `Hayvan` sınıfı sadece verileri yönetir. Ekrana çizim veya Terminal çıktıları (UI) başka modüllerin işidir.

O Open/Closed (Açık/Kapalı)

Mantık: Kod genişlemeye açık, ancak değişime kapalı olmalıdır.
Uygulama: Yeni bir hayvan türü eklerken `Hayvan` sınıfını bozmuyoruz, sadece ondan miras alan yeni bir sınıf (Zurafa vb.) ekliyoruz.

L Liskov Substitution (Yerine Geçme)

Mantık: Alt sınıflar, üst sınıfların yerine hatasız geçebilmelidir.
Uygulama: `Hayvan` tipindeki bir koleksiyonda `Aslan` nesnesi kullanıldığında, tüm ana metotlar beklenildiği gibi çalışmaya devam eder.

I Interface Segregation (Arayüz Ayrımı)

Mantık: Kimse kullanmadığı metodu barındıran interface'i uygulamaya zorlanmamalıdır.
Uygulama: `IVarlik` gibi küçük interface'ler kullanarak sınıflara sadece ihtiyacı olan yetenekleri kazandırıyoruz.

D Dependency Inversion (Bağımlılığın Tersine Çevrilmesi)

Mantık: Bağımlılıklar somut sınıflara değil, soyutlamalara (interface/abstract) olmalıdır.
Uygulama: Simülasyon motorumuz `Aslan` nesnelerine değil, `IVarlik` imzasını taşıyan her şeye hizmet verebilir.
